## 2. 拆分原则与共同完成条件

每项以能实际演示或验证的用户路径为边界。01 用登录路径带起最小工程；02–16 按业务行为同时补齐数据库、API、页面、权限、事务和验证；17、18 是已有系统的性能与交付验收，不承担前面漏做的基础测试。

1. 必要表结构、索引与约束随所属业务迁移，不先建全部表或空模块。前后端仍按批准工程结构组织，不拆成数据库组/后端组/前端组三轮交接。
2. 新写入同步产生所需业务日志和审计；15 负责查询整合，不能等到 15 才开始留痕。新增关联业务时同步扩展账号/住宿资料的停用限制。
3. 公开 HTTP API + 真实隔离 MySQL 为主要验证边界，真实浏览器验证交互；固定示例与期望值，不以原型模拟或重写实现公式当作验收。
4. 页面按第一版风格，覆盖加载/空/失败/成功反馈、可恢复输入、分页与查询限制、两种目标桌面尺寸；权限由服务端落实，查询不隐式写业务数据。
5. 每项补齐实际数据库/接口/测试及必要运行说明，完成后留下真实结果和未执行限制；18 负责全量复现与汇总。
6. 用户已批准本轮拆分并授权从 01 开始 implement；依赖与验收仍需逐项满足。不预设工期，不裁剪 P0/P1。
