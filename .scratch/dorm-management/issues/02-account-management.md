## What to build

系统管理员通过账号页面管理四类账号，账号状态和角色变化立即影响实际请求权限，并形成可追溯的管理记录。

## Acceptance criteria

- [ ] 系统管理员可创建账号、指定唯一角色、重置密码及禁用账号；账号列表具备查询和分页，不开放匿名注册。
- [ ] 非系统管理员无法通过页面、直接请求或篡改标识执行这些操作；密码不以明文存储或出现在查询结果、日志中。
- [ ] 禁用后不能登录，已有会话也不能继续请求业务；角色变更后已有会话按最新角色判断权限。
- [ ] 被业务引用的身份保留历史，不通过硬删除绕过约束；停用前检查已存在的关联业务，拒绝时展示需先处理的事项。
- [ ] 账号管理写入与关键操作记录一致提交；后续住宿、报修、卫生任务在引入关联数据时补齐对应停用检查和回归，不留到审计查询任务才记录日志。
- [ ] 真实 API 与数据库验证角色/状态切换、越权和失败回滚；浏览器完成创建、登录新账号、重置与禁用演示。
