## What to build

正式评分低于批次固定阈值时自动形成唯一未关闭整改事件，管理角色在真实列表中跟进、核实并关闭。

## Acceptance criteria

- [x] 单次综合分严格低于评分时固定阈值触发，默认 60；59.99 触发、60.00 不触发，不引入连续两次规则。
- [x] 后续方案阈值变化不回写事件依据；保存与触发成绩、批次、阈值的关联以供追溯。
- [x] 同寝室最多一条未关闭事件；重复/并发低分复用已有事件，不生成重复未关闭记录。
- [x] 系统管理员与宿舍管理员可查待整改列表、记录跟进和核实结果、填写关闭说明；无权角色不能操作。
- [x] 后续检查合格不自动关闭；核实关闭后，新的检查低分可触发新事件，既有跟进历史保留。
- [x] 评分、整改关联、必要日志保持事务一致；引入未完整改时完善相关资料停用检查，不以删除历史解决约束。
- [x] 用真实评分触发列表并在浏览器完成跟进/关闭，验证临界值、并发去重、后续合格及关闭后再次低分；不新增公告或外部推送。
