## What to build

在批准的本地前后端分离结构中，四类模拟账号能从真实浏览器登录、查看个人资料、修改密码并退出；最小持久化和测试链路随这个可演示流程一起建立。

## Acceptance criteria

- [x] 本机前端、后端和隔离的项目 MySQL 可按说明启动；浏览器通过同源 /api 代理访问后端，停止与再次启动保留数据。只创建本任务实际使用的工程内容。
- [x] 四类模拟账号登录后进入对应角色入口，展示已确认名称与第一版灰蓝新拟态布局；未实现功能不以假业务数据宣称可用。
- [x] 个人资料来自当前账号；修改密码校验合法输入且持久化生效，后续登录可验证新密码；退出后原会话不能继续调用业务接口。
- [x] 密码使用可靠单向哈希；登录 Cookie 为 HttpOnly，写请求有 CSRF 防护；未登录、越权、参数错误和服务器错误有可理解且不泄露内部信息的反馈。
- [x] 只读查询不创建业务数据；前端有加载、空、错误状态，手工输入无权页面地址不能取得业务数据。
- [x] 通过真实 MySQL 上的初始迁移与公开 HTTP API 验证，以及两种目标桌面尺寸下的登录、个人资料、改密、退出流程；形成可复用的隔离测试入口。
- [x] 实施前重新检查本机依赖、Docker 与端口，按官方兼容要求核验并锁定版本；记录实际启动方式和环境限制，不沿用历史环境探测作为当前成功证据。

## 验证与可演示结果

用四个角色分别登录、刷新、查看本人资料、改密、退出，并重放退出前会话；无 CSRF 的写请求应被拒绝。此处只验收认证与最小运行闭环，完整业务演示和干净环境复现由 18 收口。

每个功能切片同步交付必要迁移、服务端授权及事务校验、实际页面、最小模拟数据、公开 API / 真实 MySQL 验证与必要浏览器证据。相关数据库、接口、运行或测试说明随切片更新；通用完成条件见总览。
