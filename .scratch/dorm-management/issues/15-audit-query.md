## What to build

系统管理员从审计页面查询已发生的关键操作并关联业务记录，其他角色只能访问其获准的本人业务记录。

## Acceptance criteria

- [x] 查询覆盖账号/资料调整、入住调寝退宿、派单取消处理、方案变化、名单/批次状态、更正及整改管理等关键操作；字段含操作者、时间、对象、动作及该动作所需原因/前后信息。
- [x] 审计产生由对应业务任务从第一天负责，本任务整合检索、关联和展示；不把业务状态日志或更正明细搬成另一套事实。
- [x] 系统管理员可查管理审计；宿舍管理员仅查本人业务记录，学生和维修人员沿各自获准工单查看进度，不可查询全局审计。
- [x] 筛选、分页、排序白名单和敏感数据最小化有效；日志不包含密码、Session 标识或无需展示的人员信息，不提供普通业务入口改写历史。
- [x] 用真实业务操作产生记录再查询验证，成功操作记录完整、失败不留下假成功日志；跨模块历史引用与停用约束作一次集中回归。
- [x] 浏览器可从查询定位相关记录，服务端越权请求被拒；明确区分管理审计、工单状态日志与成绩更正记录。
