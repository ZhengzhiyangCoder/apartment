## What to build

系统管理员有理由地调整应检名单和批次状态，宿舍管理员看到一致的录分权限、进度和历史补录入口。

## Acceptance criteria

- [x] 系统管理员带原因补入符合条件的寝室，或移出尚未评分的错误名单项；已经评分的寝室不可移除；名单前后差异、原因、操作者可追溯。
- [x] 进度以调整后的该批次名单计算；之后入住/退宿不自动改变名单或旧周完成率，批次管理状态与进度保持分离。
- [x] 关闭和停检均禁止普通正式提交、草稿转正式；草稿仍可查看；关闭批次仍允许后续 14 的有审计更正。
- [x] 默认跨周关闭旧批次普通录入；系统管理员可带原因显式重开历史批次供宿管补录，授权不被普通跨周处理再次立即撤销。
- [x] 补录沿用原名单、方案、阈值和周一归属日，实际提交时间据实记录；重复正式评分仍受唯一约束。
- [x] 停检及恢复状态需留痕，既有成绩和草稿保留；11/12 验证停检不参加排名、平均、有效趋势样本与完成率考核，恢复后按对应状态重新纳入。
- [x] 批次状态/名单更改与同时发生的提交须遵守事务与冲突规则；不能出现移出名单后仍新增成绩等越过校验的结果。
- [x] 真实 API 与浏览器覆盖调整、关闭、停检、恢复、授权补录、无应检和草稿不可发布，并验证日志与状态一致。
