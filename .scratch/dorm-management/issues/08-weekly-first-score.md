## Acceptance criteria

- [x] 准备批次使用明确写操作；系统管理员、宿舍管理员并发准备当前 ISO 年周均返回同一批次，不提供未来周入口；只读列表不会隐式创建批次。
- [x] 按 Asia/Shanghai 和 ISO 年周确定批次，创建时固定当前启用且有学生入住的寝室及启用方案版本；周中启用新方案和入住变更不回写已有快照。
- [x] 宿舍管理员按楼栋/房号查询全校应检寝室并录分，系统管理员不冒充普通评分角色；不在名单、非允许录入状态或跨周未授权时服务端拒绝提交。
- [x] 维度必须全部且仅为绑定方案维度，分值为 0–100 整数；服务端精确十进制计算并四舍五入两位，40/30/30 权重下 80/90/70 得 80.00；不能信任客户端总分。
- [x] 保存维度名称、权重、分值、总分及阈值依据；正式评分、明细和日志同事务，失败无部分状态；同批次同寝室并发/重复提交仅一份成功，其余明确冲突。
- [x] 应检 3 间完成 2 间显示 2/3，第三间未检查而非零分；无应检显示独立空状态；100% 完成不自动关闭。
- [x] 引入应检等未完业务时同步检查关联资料停用限制；已评分记录及历史标准不硬删除。
- [x] 可控制时间的测试覆盖 ISO 跨年、下一周可再次评分、周一归属日与实际提交时间分别保存；后续显式名单/状态管理归 10，低分自动整改归 13。
