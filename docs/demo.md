## 账号管理演示

1. 用 system_admin 登录，进入侧栏“账号管理”；按账号/姓名、角色、状态查询并切换分页。
2. 创建一个新的模拟账号，填写姓名、唯一角色和初始密码。在独立浏览器会话登录该新账号。
3. 保留新账号的旧会话，用系统管理员变更其角色；旧页面下一次请求要求重新登录，新登录进入新角色工作台。
4. 重置该账号密码；旧密码不可登录，新密码可登录，旧会话失效。
5. 禁用该账号；登录与已有会话均被拒绝，账号仍保留在列表。启用后使用现有密码重新登录。
6. 尝试禁用最后一位系统管理员，系统提示先准备另一位系统管理员；重复账号名、并发版本变化和网络失败均显示错误并保留表单输入。

以上操作会真实写入演示库及审计；请创建专用模拟账号体验，保留四个基础演示账号供后续任务。账号管理只创建登录账号；学籍资料通过“住宿管理 → 学生资料”关联已有学生账号，入住关系通过“入住办理”管理。

## 住宿资料演示

显式 seed 补充模拟 A/B 两楼栋、A101/A102/B201 三间寝室，每间 01/02 两床位，以及关联 student 的 DEMO20260001 学籍资料（首次加载尚未入住，重复加载保留实际住宿状态）。数据完全虚构；若同编号/同账号资料已存在则保留，不覆盖用户编辑。它是初始化样本，不伪造用户业务操作审计；之后页面变更正常留下操作记录。

1. system_admin 登录进入“住宿管理”，四个标签分别分页展示楼栋、寝室、床位与学生资料。
2. 楼栋行“查看寝室”、寝室行“查看床位”带入父级筛选；“查看全部”返回全体。搜索和状态过滤与分页可组合使用。
3. 新增楼栋、寝室、床位，尝试重复编号，错误时保留输入；修改名称/房号/楼层/床位号后刷新仍保留。全体视图下新增子资料使用可搜索、分页的父级选择器。
4. 先在账号管理创建专用 STUDENT 模拟账号，再在学生资料中搜索选中账号并填写学号、学生姓名、学院、专业、班级。重复学号/绑定被拒，账号改为其他角色也被拒。
5. 编辑与启停资料，停用不删除。停用楼栋后尝试在其下新建寝室，提示先启用上级；子记录及历史仍可查。版本变化会提示刷新后重试。
6. dorm_manager 可查询楼栋、寝室、床位，无新增、编辑、启停按钮；不开放全体学籍列表。student/maintainer 无住宿管理入口，直访与接口均拒绝越权。

任务 04 已接入当前入住的账号及住宿资料停用保护；05已增加未完工单的同类限制，后续卫生业务继续接入。


## 入住、调寝、退宿与历史演示

最小样本复用 DEMO20260001 与模拟 A/B 栋现有床位，全部虚构。seed 不自动办理入住，也不重置已有住宿或审计，避免重复加载恢复已退宿关系。

1. system_admin 进入侧栏“入住办理”，点击“办理入住”。搜索并选择 DEMO20260001，再选模拟 A 栋 A101 的可用床位，确认入住。
2. 独立浏览器会话用 student 登录，进入“我的住宿”，显示楼栋、寝室、床位与入住时间。重新进入页面、窗口重新获得焦点或“刷新住宿”均读取最新事实。
3. 在管理页面尝试停用该账号、学生资料、楼栋、寝室或床位，提示先处理当前入住。
4. 回到“入住办理”，对当前记录“调寝”，选择另一张空床位并填写原因；学生刷新后看到新位置。目标已被占用、停用或旧窗口已办理时均拒绝并保留输入。
5. “退宿”填写说明并确认；学生刷新显示“尚未入住”。历史筛选可以查看原寝室、时间、调寝/退宿原因；按学号筛选可连续追溯。
6. 测试失败恢复可用浏览器离线再提交，恢复网络后重试；服务端始终复查当前状态。页面保留输入且不把失败当成功。

此路径真实写演示库与审计。演示结束状态由操作者决定，正常重启与 seed 均不会清空或覆盖。05已交付报修历史与原位置；成绩范围与应检名单快照仍由08/10/11完成。

## 学生图文报修演示（任务05）

2026-11-13本机已用真实API新增两张明确标记的模拟工单：student在模拟B栋B201/01提交，一张待分配、一张已取消；各含一张“模拟水龙头滴水示意”图片。重复seed与后端实际重启后，工单详情、状态日志、原住宿及图片SHA-256完全一致。seed不自动创建或恢复这些工单，后续以真实查询为准。

1. student登录进入“我的报修”，可筛选状态、搜索及分页；“查看详情”展示提交位置、图片和状态记录。
2. “新建报修”选择分类、描述和可选0–5张JPG/PNG/WebP；每张≤5MB且≤1600万像素。伪装/损坏文件被拒；失败保留文字与已选图片，恢复后重试不重复建单。
3. 待分配或待处理详情填写原因“确认取消工单”；宿管及系统管理员进入“报修管理”可按相同规则取消。重复取消提示刷新，历史始终保留。
4. 学生调寝后旧单位置不变，新单取新住宿；退宿后只能查看、取消本人历史单，不能新建。未完工单关联位置或账号停用会被拒绝，需先处理相关事项。
5. 其他学生无权获取该详情或图片；任务06已开放当前分配维修人员的任务与图片读取，重分配后原负责人失去访问权。

演示操作会真实保存，不要把实际个人资料放进模拟数据。图片位置见[运行说明](local-run.md)，API与错误码见[接口说明](api.md)。


## 派单、维修与结果演示（任务06）

1. student提交带图报修后，dorm_manager或system_admin在“报修管理”详情点“分配维修人员”，搜索并选择启用的维修账号后确认。
2. maintainer在“我的维修任务”中仅看到分配给自己的工单；详情可查看提交位置、图片、派单记录，点击“开始维修”。
3. 在处理中填写“处理说明”并“确认完成维修”；student刷新本人详情，在“处理结果”查看说明与完成时间。终态保留记录，不提供重开或改写。
4. 待处理时管理角色可带原因“重分配维修人员”；原负责人下一次请求失去列表、详情及图片访问权。开始维修后不允许普通重分配或取消。
5. 学生本人、宿管、系统管理员均可带原因取消待分配或待处理工单。维修人员无取消入口。
6. 派单、重分配和完成请求失败会保留选择/原因/处理说明；过期版本提示刷新详情。维修人员有未完任务时，系统管理员停用或改换其角色会被拒绝。

使用独立浏览器会话切换角色；如需体验转派，可在账号管理创建专用模拟MAINTAINER，任务完结后再停用。所有操作真实保存到本机演示库，正常seed不会覆盖现有分配与维修结果。
